Collection operations

Nift can transform immutable JSON arrays at build time with a small set of pure, composable collection operations. Operations keep typed values while Nift consumes them and serialize as JSON only when rendered into output.

One model, two destinations.

@sort(values) can be rendered directly into JavaScript or JSON, or passed directly to @for, @join, or another collection operation. The intermediate result remains an array inside Nift.

At a glance

OperationResult
@filter(item : items, expression)Array containing items whose expression is truthy.
@map(item : items, expression)Array containing each expression result.
@sort(items)Stable ascending copy of a scalar number/string array.
@sort(item : items, expression asc|desc)Stable copy ordered by a numeric or string key.
@slice(items, pos, length)Array slice using zero-based position and non-negative length.
@find(item : items, expression)First matching item, or null.
@some(item : items, expression)true when any item matches.
@every(item : items, expression)true when every item matches; true for an empty array.
@distinct(items)Array with later JSON-equal duplicates removed, preserving first occurrence order.
@reverse(items)Reversed copy of the array.

Simple sorting

@sort(scores)
@sort(tags)

The one-argument form accepts arrays containing only numbers or only strings and sorts ascending. It does not mutate the original binding.

Binding forms use normal expressions

The predicate, mapping expression, and sort key use the same pure expression rules documented for $[expression] and @if(expression).

@filter(post : posts, post.published && post.score >= 80)
@map(product : products, product.price * product.quantity)
@sort(post : posts, post.date desc)
@find(user : users, user.id == target_id)
@some(post : posts, post.featured)
@every(product : products, product.price > 0)

The binding exists only while that operation evaluates its items. Collection operations are pure: source arrays and existing bindings are not mutated.

Composition

Collection results remain typed while another Nift construct consumes them, so operations can be nested naturally.

@for(post : @sort(p : @filter(p : posts, p.published), p.date desc)) {
    <h2>$[post.title]</h2>
}

Or map a filtered collection and hand the resulting string array to @join:

@join(
    @map(post : @filter(post : posts, post.published), post.title),
    ', '
)

@slice makes limiting a transformed collection explicit without adding separate take/skip operations:

@for(post : @slice(@sort(p : posts, p.date desc), 0, 10)) {
    ...
}

Rendering collection values

When a collection operation reaches output instead of another Nift consumer, Nift serializes the typed result as valid JSON. This makes the operations useful in generated JavaScript as well as HTML templates.

<script>
const published = @filter(post : posts, post.published);
const titles = @map(post : posts, post.title);
const sortedScores = @sort(scores);
</script>

The generated values are JSON literals, so arrays, objects, strings, numbers, booleans and null retain their data types.

Finding and testing

@find returns the original first matching value rather than a copy transformed by the predicate. No match renders null. @some short-circuits on the first truthy match; @every short-circuits on the first falsey match.

Deliberate boundary

This is a small immutable transformation vocabulary, not a general collection-programming runtime. Nift still has no assignment, mutation, callbacks with side effects, accumulators, user-defined functions, or general query language. The useful boundary is pure values flowing through pure transforms; runtime programming remains the job of JavaScript, a backend, or another tool.
